# VRE-410 + VRE-411 Design: Infrastructure & Enrichment Prompt

> Sequential implementation: VRE-410 (infrastructure) first, then VRE-411 (enrichment prompt design).

## VRE-410: Infrastructure Setup

### D1 Database — `chatjpt-db`

Two tables:

**`articles`** — 17 columns:
- Core fields: id (PK), url, site, name, type, description, date_published, keywords (JSON), search_weight, text, schema_object (JSON)
- Enrichment fields: city, neighborhoods (JSON), categories (JSON), cuisine_type (JSON), occasion (JSON), dishes (JSON)
- Cache field: content_hash

**`article_places`** — normalized places:
- article_id (FK), name, neighborhood
- Composite PK: (article_id, name)

**Indexes:** idx_articles_city, idx_articles_type, idx_places_name

Schema SQL lives in `docs/migration-plan-d1-vectorize.md` section 1.1.

### Vectorize Index — `chatjpt-vectors`

- Dimensions: 768 (matches @cf/baai/bge-base-en-v1.5)
- Metric: cosine
- 7 metadata indexes (of 10 max): city, type, category, cuisine, occasion, neighborhood, search_weight
- Indexes must be created before any vectors are inserted

### wrangler.toml Bindings

Add `[[d1_databases]]` (binding: DB) and `[[vectorize]]` (binding: VECTORIZE) alongside existing `[ai]` binding. No Worker code changes in this phase.

### Migration

Created via `wrangler d1 migrations create`, applied to local + remote.

## VRE-411: Enrichment Prompt Design

### LLM

Workers AI — Llama 3.3 70B (same model as chatjpt.config.mjs chatModel). Used for both validation and production enrichment.

### Prompt Structure

System prompt + user message pattern:
- System prompt: defines JSON schema, extraction rules, edge case handling
- User message: raw article markdown
- Output: single JSON object, no markdown fencing

### Target Output Shape

```json
{
  "city": "Amsterdam",
  "neighborhoods": ["De Pijp", "Centrum"],
  "places": [{ "name": "Pizzeria Firma", "city": "Amsterdam", "neighborhood": "Centrum" }],
  "dishes": ["pizza margherita", "tiramisu"],
  "categories": ["diner", "lunch"],
  "cuisine_type": ["Italiaans"],
  "occasion": ["date night", "met vrienden"]
}
```

### Extraction Rules

- Extract only what's explicitly mentioned — no inference or guessing
- `city`: primary/most-discussed city if article covers multiple
- Non-food articles (fashion, culture): empty arrays for dishes, places, cuisine_type; still extract city and categories where applicable
- Dutch-first taxonomy: prefer Dutch terms (normalization map clusters later)
- Valid JSON only — no fencing, no explanation

### File Location

`src/enrichment-prompt.md` — imported as text via existing wrangler `[[rules]]` config for `.md` files.

### Validation

- 10-20 articles from existing markdown cache across all article types
- Manual review of each output
- Iterate until extraction quality is consistent across: single-venue review, multi-venue listicle, city guide, non-food article, multi-city article
